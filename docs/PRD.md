# DevBench 产品需求文档（PRD）

> **文档状态：** MVP 需求冻结 / 开发基线（修订版）
> **产品名称：** DevBench
> **中文名称：**开发者工作台
> **产品副标题：** Developer & Tester Toolbox
> **产品形态：** 纯前端 Web 应用 / PWA
> **目标平台：** 桌面浏览器、平板浏览器、移动浏览器
> **部署平台：** Cloudflare Pages

# 1. 产品概述

## 1.1 产品定位

本产品是一款面向开发人员和软件测试工程师的在线工具箱，提供常见的数据处理、日期时间转换、编码解码、哈希计算、随机数据生成、HTTP信息解析和文本比对等功能。

产品以个人使用为优先，同时兼顾未来公开分享。

核心设计原则：

1.  **即开即用：** 无需注册、登录，不设置使用门槛。
2.  **本地处理：** 工具的核心计算在用户浏览器本地完成。
3.  **轻量专业：** 页面简洁，操作直接，避免复杂的配置和不必要的交互。
4.  **跨设备：** 桌面、平板、移动端均可正常使用。
5.  **双语支持：** 支持简体中文和英文。
6.  **离线可用：** 完成首次必要资源缓存后，核心工具支持离线使用。
7.  **可维护：** 通过统一工具注册中心管理工具，降低后续维护成本。

## 1.2 目标用户

主要用户：

-   Web 软件测试工程师。
-   前端、后端及全栈开发人员。
-   日常需要处理 JSON、HTTP、编码、日期和文本数据的技术人员。

典型使用场景：

-   格式化、校验和比较 JSON。
-   转换时间戳和日期时间。
-   解析 JWT、HTTP Header 和 Cookie。
-   生成 UUID 和测试数据。
-   编码、解码或计算哈希。
-   测试正则表达式。
-   比较文本和数据结构差异。

## 1.3 产品边界

MVP 采用纯前端架构。

明确不开发：

-   用户注册、登录和账号管理。
-   后端业务服务。
-   数据库。
-   服务端文件处理。
-   云端数据同步。
-   广告和行为分析。
-   远程错误监控。
-   站内反馈系统。
-   文件上传、拖放和批量文件处理。
-   工具之间的数据自动传递。
-   完整的第三方工具插件运行时。
-   多套可自定义的首页布局预设。

未来如确实需要服务器能力，再单独评估 Cloudflare Workers 等方案，不作为 MVP 的隐含依赖。

# 3. 信息架构

## 3.1 页面路由

使用 React Router 管理页面路由。

  页面         路由               说明
  ------------ ------------------ ----------------------
  首页         `/`                工作台和工具目录入口
  工具目录     `/tools`           展示全部工具
  工具详情     `/tools/:toolId`   独立工具页面
  收藏页面     `/favorites`       收藏和置顶工具
  最近使用     `/recent`          最近使用的工具
  隐私与安全   `/privacy`         隐私处理和安全说明
  404 页面     `*`                未匹配路由

要求：

-   每个工具必须具有独立 URL。
-   支持直接访问工具 URL。
-   刷新页面后能够正确加载。
-   支持浏览器前进和后退。
-   Cloudflare Pages 必须正确配置 SPA fallback。
-   不将工具输入、计算结果或敏感参数写入 URL。

## 3.2 工具主分类

MVP 使用技术类型作为主分类，每个工具必须且只能属于一个主分类。

  `text`        文本与正则    Text & Regex               2

分类数据由统一配置管理，不得在首页、目录页和搜索页分别硬编码。

MVP 标签：

# 4. 首页与导航

## 4.1 首页定位

首页采用个人工作台与工具目录混合型布局。

主要区域：

1.  品牌标识和全局导航。
2.  全局搜索框。
3.  常用工具。
4.  最近使用。
5.  收藏工具。
6.  工具分类入口。
7.  完整工具目录入口。

首次访问时，由于不存在使用记录，不能显示大面积空白区域。

没有最近使用记录时，应使用推荐工具或分类入口填充相应区域。

## 4.2 导航布局

桌面端：

-   使用侧边栏作为主要导航。
-   页面顶部提供搜索及必要的全局操作。
-   主内容区域保持合理宽度。

移动端：

-   使用抽屉式或适配移动端的导航。
-   不允许桌面侧边栏挤压工具操作区域。
-   搜索框应方便触控操作。

平板端根据实际宽度选择合适布局。

## 4.3 全局搜索

支持搜索：

-   工具中文名称。
-   工具英文名称。
-   工具别名。
-   工具关键词。
-   工具描述。
-   功能标签。

搜索规则：

-   中英文混合搜索。
-   大小写不敏感。
-   支持关键词匹配。
-   按相关性排序。
-   搜索结果来自工具注册中心。
-   不为搜索单独维护重复工具列表。

快捷键：

-   Windows/Linux：`Ctrl + K`
-   macOS：`Cmd + K`

快捷键用于聚焦全局搜索框。

没有搜索结果时，应提供明确提示，并提供工具分类或完整目录入口。

## 4.4 收藏与置顶

支持用户收藏工具和置顶工具。

两者语义独立：

-   收藏：表示用户希望保留或经常访问。
-   置顶：表示用户希望在列表中优先看到。

排序规则：

-   置顶工具优先显示。
-   收藏工具默认按照收藏时间排序。
-   常用工具按照使用频率排序。
-   最近使用按照最近使用时间排序。

不支持首页模块拖拽、隐藏、调整大小或自定义顺序。

## 4.5 最近使用

最近使用记录：

-   工具 ID。
-   最近使用时间。

规则：

-   最多保留 10 个工具。
-   重复使用时更新对应记录的最近使用时间。
-   用户成功进入工具页面后记录。
-   页面预加载、搜索结果展示不触发使用记录。
-   支持清空最近使用。
-   清空最近使用不影响收藏和置顶。

# 5. 全局偏好与本地状态

## 5.1 允许持久化的数据

使用 LocalStorage 保存少量非敏感的用户偏好：

-   主题模式。
-   当前语言。
-   收藏工具。
-   置顶工具。
-   最近使用记录。
-   少量非敏感工具偏好，例如 JSON 缩进设置。

不建立复杂的本地数据库。

## 5.2 禁止持久化的数据

以下内容不得写入任何持久化存储：

-   用户输入。
-   工具处理结果。
-   JWT。
-   Cookie。
-   Authorization Header。
-   Token。
-   密码。
-   其他可能包含敏感信息的数据。

不得使用以下位置保存用户输入和结果：

-   LocalStorage。
-   SessionStorage。
-   IndexedDB。
-   URL 查询参数。
-   浏览器历史记录。
-   Service Worker Cache。
-   应用日志。
-   控制台日志。

工具输入和计算结果只保存在当前页面的局部运行状态中。

页面刷新、关闭或离开后，不恢复输入和结果。

## 5.3 LocalStorage 异常处理

必须考虑：

-   本地数据不存在。
-   JSON 数据损坏。
-   数据版本不兼容。
-   存储被浏览器禁用。
-   存储空间不足。
-   写入失败。

要求：

1.  本地偏好读取失败时使用合理默认值。
2.  损坏的偏好数据不得导致应用崩溃。
3.  允许重置无法读取的偏好数据。
4.  写入失败不得影响工具核心功能。
5.  不得因为偏好存储失败而尝试上传数据到服务器。

建议为持久化偏好定义 schema 版本和迁移策略。

# 6. 工具页面通用规范

## 6.1 页面基本结构

每个工具页面至少包含：

1.  工具名称。
2.  工具简短说明。
3.  输入区域。
4.  必要的参数配置。
5.  操作按钮。
6.  结果区域。
7.  错误或状态提示。
8.  可折叠的使用说明。
9.  相关工具入口。

## 6.2 输入和结果

必须遵循：

-   原始输入与结果分离。
-   处理结果不得覆盖原始输入。
-   用户可以重新编辑输入。
-   根据工具特点选择实时处理或按钮触发。
-   空输入不应产生误导性的错误。
-   非法输入必须显示明确错误。
-   长任务需要展示处理中状态。
-   结果区域不得无限扩展页面高度。

## 6.3 交互模式

采用混合交互模式：

  类型       交互方式             适用场景
  ---------- -------------------- -----------------------
  简单转换   实时处理             URL、Unicode 等
  复杂处理   点击按钮执行         JSON Diff、哈希计算等
  数据生成   点击按钮生成         UUID、随机数据等
  配置驱动   参数变化后按需更新   日期格式化等

不得强制所有工具采用同一种执行模式。

## 6.4 统一操作能力

按工具实际需要提供：

-   清空输入。
-   复制结果。
-   下载结果。
-   处理中状态。
-   错误提示。
-   空结果提示。
-   超限提示。
-   长结果滚动或折叠。

不要求每个工具都具备下载能力。

## 6.5 快捷键

支持全局搜索快捷键 `Ctrl + K` / `Cmd + K`。

其他工具快捷键按需配置，例如：

-   `Ctrl + Enter`：执行当前工具操作。

具体快捷键必须逐项检查冲突：

-   不覆盖浏览器和操作系统的核心快捷键。
-   用户正在输入文本时，不应误触发与当前输入冲突的操作。
-   保留可见按钮，不能只提供快捷键操作。
-   快捷键说明支持中英文。

## 6.6 工具说明

每个工具提供简短、可折叠的说明，至少包括：

-   工具用途。
-   输入格式。
-   使用示例。
-   关键参数。
-   常见错误。
-   注意事项。

不要求编写完整教程。

## 6.7 相关工具

每个工具页面底部展示 2--4 个相关工具。

要求：

-   使用静态元数据配置关联关系。
-   点击后直接跳转对应工具页面。
-   不自动传递当前工具输入或结果。
-   不建立跨工具工作流。
-   注册元数据预留 `relatedTools` 字段。

# 7. 20 个工具详细需求

## 7.1 JSON 格式化与校验

**工具 ID：** `json-formatter`

功能：

-   输入 JSON 文本。
-   JSON 语法校验。
-   Pretty 格式化。
-   Minify 压缩。
-   2 空格或 4 空格缩进。
-   显示格式化结果。
-   尽可能精确地提示错误行列。

规则：

-   保留对象属性原有顺序。
-   不主动对对象属性排序。
-   不覆盖原始输入。
-   空输入不报错。
-   默认缩进 2 空格。
-   初始输入限制 5 MB。

特殊边界：

-   处理非法 JSON。
-   处理尾随逗号。
-   处理字符串转义错误。
-   处理数字格式错误。
-   对重复属性名需要有明确策略。

重复属性名：

JSON 标准和 JavaScript 常见解析器对重复属性名的处理可能存在差异。

实现必须明确说明采用的解析行为，不得声称能够无损保留重复属性。

如果当前解析器无法可靠检测重复属性名，应在工具说明中说明限制，不得静默宣称不存在重复属性。

## 7.2 时间戳转换器

**工具 ID：** `timestamp-converter`

功能：

-   时间戳转日期时间。
-   日期时间转时间戳。
-   支持秒级时间戳。
-   支持毫秒级时间戳。
-   本地时区显示。
-   UTC 显示。
-   ISO 8601 显示。
-   当前时间快捷填充。

规则：

-   不静默猜测秒和毫秒。
-   用户必须能够明确选择时间戳单位。
-   无时区日期时间按用户选择的时区解释。
-   明确区分本地时间、UTC 和带时区时间。
-   考虑夏令时。
-   显示无效输入原因。

## 7.3 UUID 生成器

**工具 ID：** `uuid-generator`

功能：

-   生成 UUID v4。
-   默认生成 1 条。
-   支持批量生成。
-   单次最多 100 条。
-   支持复制单条结果。
-   支持复制全部结果。

随机数要求：

-   使用 `crypto.randomUUID()` 或 `crypto.getRandomValues()`。
-   禁止使用 `Math.random()` 生成 UUID。
-   不得在安全随机数 API 不可用时静默降级到普通随机数。

## 7.4 Base64 编解码

**工具 ID：** `base64-converter`

功能：

-   文本转 Base64。
-   Base64 转文本。
-   支持标准 Base64。
-   支持 URL-safe Base64。
-   支持中文、日文、Emoji 等 Unicode 文本。

规则：

-   使用 UTF-8 处理文本。
-   正确处理非 ASCII 字符。
-   对非法 Base64 提示错误。
-   初始输入限制 5 MB。
-   不支持文件和任意二进制文件转换。

性能与内存约束：

-   5 MB 是初始输入上限，不代表处理过程只占用 5 MB 内存。
-   编码和解码实现应避免不必要的完整字符串、字节数组和中间结果重复复制。
-   优先采用适合大文本的转换方式；不得在主线程中进行明显会造成界面长时间无响应的同步处理。
-   对处理前后可能产生的临时内存占用进行评估，尤其注意 Base64
    编码后数据体积增长。
-   当设备或浏览器无法安全处理当前输入规模时，应在执行前或执行过程中明确提示，不得持续分配内存直至页面崩溃。
-   根据真实设备测试确定最终输入上限；如需降低上限，必须同步更新界面提示、文档和测试。
-   Worker
    或分块处理是否采用，由实际性能测试决定；不得为了架构复杂度而强制引入。

## 7.5 URL 编解码

**工具 ID：** `url-encoder`

功能：

-   URL 编码。
-   URL 解码。
-   URI 编码。
-   URI 解码。
-   组件编码。
-   组件解码。

必须区分：

-   `encodeURI`
-   `decodeURI`
-   `encodeURIComponent`
-   `decodeURIComponent`

规则：

-   正确处理 Unicode。
-   非法百分号编码显示错误。
-   不将不同编码方式混为一谈。
-   说明不同方法对保留字符的处理差异。

## 7.6 MD5 / SHA 哈希计算

**工具 ID：** `hash-generator`

支持算法：

-   MD5。
-   SHA-1。
-   SHA-256。
-   SHA-384。
-   SHA-512。

功能：

-   输入文本。
-   选择算法。
-   计算摘要。
-   复制结果。

规则：

-   默认 SHA-256。
-   使用 UTF-8 编码输入。
-   SHA 系列优先使用 Web Crypto API。
-   MD5 使用本地 JavaScript 实现。
-   根据实际性能测试确定最终输入大小限制。
-   不得将哈希误称为加密。

性能与内存约束：

-   不得假设哈希输入大小等于处理过程的峰值内存占用。
-   对需要整体读取输入的 Web Crypto API 调用，应评估输入字符串、UTF-8
    编码字节数组和摘要处理所需内存。
-   避免无必要地同时保留多份完整输入副本。
-   大输入处理不得长期阻塞主线程；根据实际设备测试决定是否使用 Worker。
-   如果所选算法或实现无法安全处理当前输入规模，应明确提示并阻止继续执行，不得因内存不足导致页面崩溃。
-   不得静默截断输入或返回不完整摘要。
-   最终输入限制必须通过桌面和移动设备测试确定，并同步反映在界面、文档和测试中。

安全说明：

-   MD5 和 SHA-1 不适合安全敏感用途。
-   哈希计算不等于加密。
-   不承诺哈希结果能够用于密码存储或密码安全验证。

## 7.7 JWT 解析器

**工具 ID：** `jwt-decoder`

功能：

-   输入 JWT。
-   解析 Header。
-   解析 Payload。
-   展示 Signature 部分。
-   对 Header 和 Payload 中的 JSON 进行格式化。
-   解释常见声明字段。

支持说明的字段：

-   `iss`
-   `sub`
-   `aud`
-   `exp`
-   `nbf`
-   `iat`
-   `jti`

规则：

-   只进行本地解码。
-   不进行签名验证。
-   不访问远程密钥。
-   不访问外部服务器。
-   初始输入限制 1 MB。
-   不保存 JWT。
-   不记录 JWT。
-   不将 JWT 放入 URL。

必须明确提示：

> Decoding a JWT does not verify its signature or authenticity.

## 7.8 HTTP Header 解析器

**工具 ID：** `http-header-parser`

功能：

-   输入原始 HTTP Header。
-   解析 Header 名称和值。
-   显示解析结果。
-   保留重复 Header。
-   保留原始顺序。

规则：

-   按第一个冒号分割 Header 名称和值。
-   Header 名称大小写不敏感。
-   不得丢弃重复字段。
-   非法行应单独标记。
-   初始输入限制 512 KB。
-   不保存敏感 Header 内容。

## 7.9 JSON 比对工具

**工具 ID：** `json-diff`

功能：

-   左右两侧分别输入 JSON。
-   比较两个 JSON 结构。
-   展示差异路径。
-   展示差异类型。
-   展示原值和新值。

比较规则：

-   对象按属性名比较。
-   对象属性顺序不影响比较结果。
-   数组按索引比较。
-   数组顺序影响比较结果。
-   基本类型严格区分。
-   `null` 与其他类型不同。

差异类型至少包括：

-   新增。
-   删除。
-   修改。

结果应显示 JSON Path。

初始限制：左右单侧各 2 MB。

差异展示不能仅依赖颜色，还必须提供文字或图标辅助。

## 7.10 正则表达式测试器

**工具 ID：** `regex-tester`

功能：

-   输入 JavaScript 正则表达式。
-   输入测试文本。
-   设置 flags。
-   展示匹配结果。
-   展示匹配位置。
-   展示捕获组。
-   对匹配内容进行高亮。

支持 flags：

-   `g`
-   `i`
-   `m`
-   `s`
-   `u`
-   `y`
-   `d`（以运行环境支持为准）

规则：

-   使用 JavaScript RegExp 语法。
-   初始测试文本限制 100 KB。
-   全局匹配必须限制结果数量。
-   避免无限匹配循环。
-   必须使用 Web Worker 隔离正则执行。
-   必须设置执行超时。
-   超时后终止对应 Worker。
-   不允许危险正则长期阻塞主线程。

## 7.11 日期时间格式化

**工具 ID：** `datetime-formatter`

功能：

-   输入日期时间。
-   选择预设格式。
-   自定义日期时间格式。
-   本地时区显示。
-   UTC 显示。
-   ISO 8601 显示。

技术要求：

-   建议使用 `date-fns`。
-   涉及 IANA 时区转换时使用适配库，例如 `date-fns-tz`。
-   格式符号遵循实际采用的库。
-   不混用 Moment.js 格式符号。
-   明确区分带时区日期时间和无时区日期时间。
-   初始输入基线 10 KB。

## 7.12 日期计算器

**工具 ID：** `date-calculator`

功能：

-   计算两个日期之间的差值。
-   日期增加指定天数。
-   日期减少指定天数。
-   展示总天数。
-   展示日历年、月、日差。

规则：

-   纯日期计算不应受到夏令时造成的小时偏差影响。
-   日期加减按日历日期处理。
-   月末规则：目标月份不存在对应日期时，取目标月份最后一天。

例如：

-   1 月 31 日增加 1 个月，结果为 2 月最后一天。
-   闰年和非闰年必须得到正确结果。

日期差算法必须统一：

-   总天数按两个纯日期之间的日历日差计算。
-   年、月、日差按明确的日历分解规则计算。
-   不得将毫秒差直接除以 24 小时作为所有日期差的唯一实现方式。

## 7.13 随机字符串生成器

**工具 ID：** `random-string-generator`

功能：

-   生成随机字符串。
-   配置生成长度。
-   配置生成数量。
-   选择字符集。
-   排除易混淆字符。

默认值：

-   长度 16。
-   数量 1。

范围：

-   长度 1--1024。
-   数量 1--100。

字符集：

-   数字。
-   小写字母。
-   大写字母。
-   特殊字符。
-   自定义字符集。

随机数要求：

-   使用 `crypto.getRandomValues()`。
-   使用无偏采样。
-   禁止 `Math.random()`。
-   字符集为空时提示错误。
-   不得静默降级为普通随机数。

安全说明：

不承诺生成结果必然满足所有密码安全要求，用户应根据具体系统的密码策略自行判断。

## 7.14 随机测试数据生成器

**工具 ID：** `test-data-generator`

功能：

-   批量生成模拟测试数据。
-   支持多字段组合。
-   输出 JSON。
-   支持配置生成数量。

范围：

-   默认 10 条。
-   最少 1 条。
-   最多 10,000 条。

支持字段类型：

-   模拟姓名。
-   测试邮箱。
-   合成手机号。
-   年龄。
-   整数。
-   小数。
-   布尔值。
-   日期。
-   UUID。
-   固定文本。

规则：

-   所有数据在本地生成。
-   测试邮箱使用 `example.com` 等保留测试域。
-   不生成真实用户个人信息。
-   不生成真实身份证号。
-   不生成可用于真实身份验证的银行卡或类似敏感凭据。
-   手机号必须使用明确标记为合成数据的规则，避免冒用真实号码。
-   不得声称生成的数据一定符合真实业务系统的全部校验规则。

## 7.15 Unicode 编解码

**工具 ID：** `unicode-converter`

功能：

-   普通文本转 Unicode 转义。
-   Unicode 转义转普通文本。
-   支持中文。
-   支持日文。
-   支持 Emoji。
-   支持 UTF-16 代理对。

规则：

-   正确处理非 BMP 字符。
-   区分 Unicode 转义与 UTF-8 字节编码。
-   不得将两种编码概念混为一谈。
-   非法转义序列需要明确提示。

## 7.16 HTML 实体编解码

**工具 ID：** `html-entity-converter`

功能：

-   文本转 HTML 实体。
-   HTML 实体转文本。
-   支持常见字符。

至少包括：

-   `&`
-   `<`
-   `>`
-   `"`
-   `'`

支持：

-   十进制数字实体。
-   十六进制数字实体。

安全要求：

-   解码结果按纯文本展示。
-   禁止执行解码后的 HTML。
-   禁止将用户输入直接注入不安全 HTML。
-   不使用不必要的 `dangerouslySetInnerHTML`。

## 7.17 JSON / YAML 转换

**工具 ID：** `json-yaml-converter`

功能：

-   JSON 转 YAML。
-   YAML 转 JSON。
-   双向转换。
-   默认缩进 2 空格。

规则：

-   使用本地 YAML 库。
-   支持 JSON 基本数据类型映射。
-   不执行 YAML 自定义标签。
-   不加载外部资源。
-   对 YAML 别名展开设置合理限制。
-   明确说明无法无损映射的 YAML 结构。
-   不得承诺所有 YAML 内容都能无损转换为 JSON。
-   初始输入限制 2 MB。

## 7.18 HTTP Cookie 解析器

**工具 ID：** `http-cookie-parser`

必须区分两种输入：

1.  Cookie 请求头。
2.  Set-Cookie 响应头。

解析字段：

-   Name。
-   Value。
-   Domain。
-   Path。
-   Expires。
-   Max-Age。
-   Secure。
-   HttpOnly。
-   SameSite。

规则：

-   Expires 中的逗号不能作为简单分隔符。
-   不得将多个 Set-Cookie 响应字段简单合并后再解析。
-   保留输入中可识别的字段。
-   不自动解码 Cookie 值。
-   不保存或上传 Cookie。
-   初始输入限制 256 KB。

## 7.19 HTTP 状态码查询

**工具 ID：** `http-status-codes`

功能：

-   根据状态码查询。
-   根据名称查询。
-   根据关键词查询。
-   按状态码类别展示。
-   展示状态码名称和简短说明。

类别：

-   1xx。
-   2xx。
-   3xx。
-   4xx。
-   5xx。

规则：

-   使用本地静态数据。
-   不依赖外部 API。
-   对未分配或不常见的状态码，不得编造解释。
-   搜索支持中英文关键词。

## 7.20 文本 Diff 比对

**工具 ID：** `text-diff`

功能：

-   左右两侧输入文本。
-   行级比较。
-   展示新增、删除和修改内容。
-   保留空行。
-   展示差异位置。

规则：

-   默认区分大小写。
-   默认区分空格和 Tab。

-   不应因纯换行符差异产生大量无意义差异。

差异展示必须同时提供颜色和非颜色信息，不能只依赖颜色。

# 8. 工具分类、注册中心与元数据

## 8.1 设计目标

建立统一工具注册中心，作为整个应用的工具元数据来源。

以下模块必须由注册中心驱动：

-   首页工具列表。
-   工具目录。
-   分类页面内容。
-   全局搜索。
-   收藏工具展示。
-   最近使用展示。
-   相关工具展示。
-   工具路由匹配。

禁止在多个页面重复维护相同工具清单。

## 8.2 工具元数据

每个工具至少包含：

  字段             类型                说明
  ---------------- ------------------- ------------------
  `id`             string              唯一工具 ID
  `name`           LocalizedText       中英文名称
  `description`    LocalizedText       中英文描述
  `categoryId`     string              所属主分类
  `tags`           string\[\]          功能标签
  `keywords`       LocalizedKeywords   中英文搜索关键词
  `icon`           string              图标标识
  `route`          string              独立路由
  `component`      Lazy Component      页面组件
  `recommended`    boolean             是否推荐
  `relatedTools`   string\[\]          相关工具 ID

## 8.3 TypeScript 类型建议

``` ts
type Locale = "zh-CN" | "en-US";

interface LocalizedText {
  "zh-CN": string;
  "en-US": string;
}

interface LocalizedKeywords {
  "zh-CN": string[];
  "en-US": string[];
}

interface ToolDefinition {
  id: string;
  name: LocalizedText;
  description: LocalizedText;
  categoryId: string;
  tags: string[];
  keywords: LocalizedKeywords;
  icon: string;
  route: string;
  component: React.LazyExoticComponent<
    React.ComponentType
  >;
  recommended: boolean;
  relatedTools: string[];
}

interface ToolCategory {
  id: string;
  name: LocalizedText;
  description: LocalizedText;
  icon: string;
  order: number;
}
```

具体组件接口可以根据项目实际实现进一步细化，但不得破坏上述元数据职责。

## 8.4 注册中心校验

应用启动或测试阶段必须校验：

-   工具 ID 唯一。
-   路由唯一。
-   分类 ID 存在。
-   标签 ID 存在。
-   中英文名称完整。
-   中英文描述完整。
-   中英文搜索关键词完整。
-   图标标识有效。
-   工具组件可以加载。
-   `recommended` 为布尔值。
-   相关工具 ID 存在。
-   相关工具不能重复。
-   相关工具不能包含自身。
-   每个工具的相关工具数量为 2--4 个。
-   每个工具必须且只能属于一个主分类。

新增工具时，需要同时提供：

1.  核心处理逻辑。
2.  页面组件。
3.  注册元数据。
4.  中英文文案。
5.  单元测试。
6.  必要的组件测试。

MVP 只实现内部注册机制，不实现第三方动态插件系统。

采用静态关联配置。

  日期时间格式化   时间戳、日期计算
  日期计算         日期时间格式化、时间戳
  随机字符串       UUID、随机测试数据、哈希
  随机测试数据     UUID、随机字符串、JSON 格式化
  Unicode          HTML 实体、URL、Base64
  HTML 实体        Unicode、URL、Base64
  JSON/YAML        JSON 格式化、JSON Diff、文本 Diff
  Cookie           HTTP Header、JWT、Base64
  HTTP 状态码      HTTP Header、Cookie、JWT
  文本 Diff        JSON Diff、Regex、JSON 格式化

# 11. 视觉与交互设计

## 11.1 视觉方向

整体采用：**极简专业 + 现代科技感。**

设计原则：

# 13. 本地处理、隐私与安全

## 13.1 数据处理原则

用户输入和处理结果默认只在浏览器本地处理。

产品不会主动将用户输入和结果发送到服务器。

MVP 不接入：

-   广告。
-   行为分析。
-   访问统计。
-   远程错误监控。
-   外部业务 API。

## 13.2 网络请求约束

允许：

-   应用本身的必要静态资源请求。
-   用户主动访问外部链接。

不允许：

-   上传工具输入。
-   上传工具结果。
-   发送 JWT、Cookie 或 Token。
-   发送 Authorization Header 内容。
-   将用户数据发送到第三方统计服务。
-   将错误输入发送到远程日志系统。

测试时必须检查请求 URL、查询参数、请求头、请求体、应用日志和 Service
Worker 缓存，确保没有非预期的用户输入和处理结果传输。

## 13.3 敏感信息处理

重点保护：

-   JWT。
-   Cookie。
-   Authorization Header。
-   Token。
-   密码。
-   业务数据。

要求：

-   不持久化。
-   不上传。
-   不写入控制台。
-   不写入应用日志。
-   不写入 URL。
-   不进入 Service Worker 缓存。
-   不进入全局 Store。

离开工具页面后，页面局部状态应被释放。

不承诺浏览器能够对 JavaScript 内存进行可验证的物理擦除。

## 13.4 HTML 安全

-   不执行用户输入。
-   不将解码后的 HTML 作为可执行内容渲染。
-   避免使用 `dangerouslySetInnerHTML`。
-   对需要展示的文本使用安全的文本渲染方式。
-   避免不必要的第三方脚本。

## 13.5 CSP 与依赖安全

-   配置合理的 Content Security Policy。
-   限制外部脚本来源。
-   不依赖不必要的第三方 CDN。
-   定期检查依赖漏洞。
-   不在公开仓库中提交 API Key、Token、密码或其他秘密配置。

## 13.6 隐私说明

隐私页面必须准确说明：

1.  工具计算主要在浏览器本地完成。
2.  产品不会主动将用户输入和结果发送服务器。
3.  产品不接入应用级行为统计。
4.  用户输入和结果不会被产品主动持久化。
5.  浏览器扩展、恶意脚本、设备本身和浏览器环境仍可能影响数据安全。
6.  托管平台可能处理正常静态资源请求所需的网络元数据。

不得使用"绝对安全""任何情况下都不会泄露"等无法保证的表述。

# 14. 输入大小与性能约束

## 14.1 初始输入限制

所有大小按 UTF-8 字节数计算。

统一定义：

-   1 KB = 1024 bytes。
-   1 MB = 1024 × 1024 bytes。

  工具                     初始限制
  ---------------- ----------------
  JSON 格式化                  5 MB
  JSON Diff               单侧 2 MB
  Base64                       5 MB
  URL 编解码                   5 MB
  JWT                          1 MB
  HTTP Header                512 KB
  HTTP Cookie                256 KB
  Regex 测试文本             100 KB
  Text Diff               单侧 1 MB
  JSON/YAML                    2 MB
  日期时间格式化              10 KB
  随机测试数据       单次 10,000 条

其他工具根据其处理特点设置合理限制。

以上是初始基线，最终限制必须结合真实设备测试确定。

## 14.2 性能要求

目标：

-   正常网络环境下首次页面加载尽量控制在 3 秒以内。
-   工具页面切换通常在 1 秒以内。
-   普通输入交互尽量在 100 ms 内响应。
-   复制操作应立即给出反馈。
-   大型编辑器和语言扩展按需加载。
-   大型任务不能永久阻塞 UI。

以上指标需要明确测试设备、网络条件和测试方法，不作无条件性能承诺。

## 14.3 大任务处理

根据工具特点选择：

-   防抖。
-   Web Worker。
-   分块处理。
-   任务取消。
-   超时控制。
-   输入大小限制。

Regex 必须使用 Worker。

其他工具是否使用 Worker 根据实际测试决定。

## 14.4 Worker 生命周期

所有使用 Worker 的工具应考虑：

1.  Worker 初始化。
2.  正常执行。
3.  执行完成。
4.  执行异常。
5.  执行超时。
6.  用户取消。
7.  Worker 意外终止。
8.  Worker 初始化失败。

要求：

-   正确处理 Worker 消息。
-   避免重复执行和过期结果覆盖新结果。
-   超时或取消后及时终止对应任务。
-   清理事件监听。
-   显示可理解的错误信息。
-   不因 Worker 失败导致整个应用崩溃。

## 14.5 大型文本处理的内存与稳定性

输入大小限制不等于处理过程的峰值内存限制。字符串、UTF-8
字节数组、中间缓冲区、编码结果和最终结果可能同时占用内存。

所有处理较大文本的工具必须：

-   评估输入、输出和临时数据的峰值内存占用。
-   避免不必要地复制完整输入或结果。
-   在处理前检查输入大小，超过限制时明确拒绝执行。
-   不得静默截断输入或返回不完整结果。
-   处理过程中出现内存或资源不足时，显示可理解的错误，并停止后续处理。
-   不得持续分配内存直至浏览器标签页崩溃。
-   根据实际设备测试决定是否使用 Worker、分块处理或取消机制。
-   Worker 只能改善主线程响应性，不能被视为消除内存上限的手段。

### Base64 专项要求

-   编码和解码应避免不必要的完整字符串、字节数组和中间结果重复复制。
-   评估 Base64 编码后数据体积增长以及解码过程中的临时内存。
-   不得在主线程中执行明显会造成界面长时间无响应的同步处理。
-   设备无法安全处理当前输入规模时，应明确提示，不得持续分配内存直至页面崩溃。
-   Worker
    或分块处理是否采用，由实际性能测试决定，不强制引入不必要的架构复杂度。

### 哈希计算专项要求

-   不得假设哈希输入大小等于处理过程的峰值内存占用。
-   对需要整体读取输入的 Web Crypto API 调用，应评估输入字符串、UTF-8
    编码字节数组和摘要处理所需内存。
-   避免无必要地同时保留多份完整输入副本。
-   大输入处理不得长期阻塞主线程；根据实际设备测试决定是否使用 Worker。
-   如果所选算法或实现无法安全处理当前输入规模，应明确提示并阻止继续执行。
-   不得静默截断输入或返回不完整摘要。
-   最终输入限制必须通过桌面和移动设备测试确定，并同步反映在界面、文档和测试中。

# 15. PWA 与离线能力

## 15.1 PWA 目标

使用 `vite-plugin-pwa` 和 Workbox。

支持：

-   添加到桌面。
-   添加到手机主屏幕。
-   离线访问。
-   离线使用 20 个核心工具。

## 15.2 首次访问

首次访问需要网络。

在必要资源缓存完成之前，不得显示"离线就绪"。

必要资源包括：

-   首页。
-   工具目录。
-   20 个工具页面所需的 JavaScript。
-   工具运行依赖。
-   CodeMirror 资源。
-   Worker 脚本。
-   工具静态数据。
-   必要字体。
-   必要图标。
-   隐私说明页面。

## 15.3 离线资源要求

首次缓存完成后：

-   首页可以离线打开。
-   工具目录可以离线打开。
-   20 个工具均可以离线打开。
-   隐私页面可以离线打开。
-   未曾访问过的工具页面也必须可以离线打开。

不能因为采用懒加载，就遗漏某个工具的离线必要资源。

MVP 不依赖外部 API 或 CDN。

## 15.4 缓存策略

  资源            缓存策略
  --------------- -----------------------------
  HTML            Network First，离线回退缓存
  带哈希 JS/CSS   Cache First
  本地静态图标    Cache First
  必要字体        Cache First
  Worker 资源     纳入版本化必要资源缓存

必须确保用户输入和处理结果永不进入 Service Worker 缓存。

## 15.5 更新机制

要求：

-   检测到新版本时提示用户。
-   用户可以暂缓更新。
-   用户确认后再刷新页面。
-   新版本必要资源先缓存，再切换。
-   激活新版本后清理不再需要的旧缓存。
-   更新不得突然中断用户正在进行的操作。

更新提示必须说明：刷新页面会清空当前工具页面的输入和处理结果。

由于 MVP 不保存工具输入和结果，不提供恢复机制。

# 16. 响应式设计

## 16.1 桌面端

-   使用侧边栏导航。
-   工具页面优先采用左右布局。
-   输入和结果区域合理分配空间。
-   编辑器和结果区域不能无限扩展。

## 16.2 平板端

-   根据实际可用宽度自适应。
-   必要时调整左右布局比例。
-   避免导航挤压主要操作区域。

## 16.3 移动端

-   使用移动端导航或抽屉。
-   工具页面默认采用上下布局。
-   输入框、按钮和操作控件方便触控。
-   结果区域支持滚动和折叠。
-   不出现明显横向溢出。

## 16.4 Diff 特殊布局

JSON Diff 和文本 Diff 需要专门处理移动端布局。

不能简单地将桌面端双栏布局缩小后直接用于手机。

应确保：

-   左右输入区域均可操作。
-   差异结果可阅读。
-   差异标识清晰。
-   不出现难以操作的横向滚动区域。

# 19. 测试策略

## 19.1 测试分层

  测试类型           工具                    主要目标
  ------------------ ----------------------- ------------------------
  核心逻辑单元测试   Vitest                  验证工具处理结果
  组件与交互测试     React Testing Library   验证页面操作
  端到端测试         Playwright              验证完整用户流程
  无障碍测试         axe-core                检查常见无障碍问题
  真实设备测试       浏览器与设备            验证兼容性、PWA 和交互

## 19.2 工具测试要求

20 个工具均必须覆盖：

-   正常输入。
-   空输入。
-   非法输入。
-   边界输入。
-   正确结果。
-   复制行为。
-   输入大小限制。
-   异常处理。

对具有特殊风险的工具，增加专项测试。

## 19.3 专项测试

**JSON**

-   重复属性名。
-   非法 JSON。
-   深层嵌套。
-   大输入。

**日期时间**

-   闰年。
-   月末日期。
-   夏令时。
-   不同时区。
-   无效日期。
-   时间戳秒与毫秒。

**HTTP Cookie**

-   Expires 中的逗号。
-   重复 Set-Cookie。
-   不同属性组合。
-   非法输入。

**Worker**

-   超时。
-   取消。
-   初始化失败。
-   执行异常。
-   意外终止。
-   旧任务结果覆盖新任务。

**Base64 和哈希**

-   接近输入上限的数据。
-   UTF-8 多字节字符。
-   大输入下的内存占用和处理耗时。
-   主线程响应性。
-   Worker 失败或取消（如果采用 Worker）。
-   资源不足时的错误提示。
-   不得静默截断或返回错误摘要。

**PWA**

-   首次缓存完成。
-   离线访问首页。
-   离线访问工具目录。
-   离线访问从未打开过的工具。
-   更新暂缓。
-   更新确认。
-   旧缓存清理。

**LocalStorage**

-   数据损坏。
-   版本不兼容。
-   写入失败。
-   存储不可用。

**隐私**

-   输入不进入 LocalStorage。
-   输入不进入 SessionStorage。
-   输入不进入 IndexedDB。
-   输入不进入 URL。
-   输入不进入 Service Worker Cache。
-   输入不进入日志。
-   不存在非预期网络请求。

## 19.4 核心页面 E2E

至少覆盖：

-   首页。
-   工具目录。
-   全局搜索。
-   工具页面。
-   收藏。
-   最近使用。
-   隐私说明。
-   404。

全局交互至少覆盖：

-   主题切换。
-   语言切换。
-   收藏和取消收藏。
-   置顶和取消置顶。
-   最近使用。
-   清空最近使用。
-   页面刷新。
-   直接访问工具路由。
-   浏览器前进和后退。
-   离线访问。

## 19.5 本地质量门禁

每次提交前运行：

``` bash
npm run lint
npm run typecheck
npm run test
npm run test:e2e
npm run build
```

实际命令名称以项目 `package.json` 为准。

关键检查失败时，不得将该次提交视为通过质量门禁。

建议在本地使用静态服务器预览生产构建产物，验证实际部署行为。

MVP 不要求建立 GitHub Actions 自动化流水线。

# 20. 部署与版本管理

## 20.1 部署方案

使用 Cloudflare Pages 静态部署。

要求：

-   不开发后端。
-   不使用数据库。
-   不配置账号系统。
-   不设置访问密码。
-   公开访问。
-   使用 GitHub Public 仓库。

## 20.2 Git 管理

采用：

-   `main` 作为唯一长期开发分支。
-   直接在 `main` 开发和提交。
-   不使用 Git Flow。
-   不建立额外 Feature 分支流程。

仅 `main` 分支自动部署正式网站。

不建立独立 Preview 或线上测试环境。

## 20.3 GitHub Actions

MVP 不使用 GitHub Actions。

代码检查、测试和构建由本地人工执行。

## 20.4 Cloudflare Pages

需要正确配置：

-   构建命令。
-   构建输出目录。
-   SPA fallback。
-   PWA 静态资源。
-   必要的安全响应头。
-   CSP。

## 20.5 环境变量与秘密管理

公开仓库不得提交：

-   API Key。
-   Token。
-   密码。
-   私有密钥。
-   个人信息。
-   其他秘密配置。

提供 `.gitignore` 和 `.env.example`。

`.env.example` 只能包含变量名称和非敏感示例值，不能包含真实秘密。

MVP 不应因为预留环境变量而引入不必要的服务端依赖。

# 23. 非功能需求与验收标准

## 23.1 功能验收

-   20 个工具均可正常访问。
-   每个工具均有独立路由。
-   每个工具的核心功能符合本 PRD。
-   工具输入与结果分离。
-   搜索可以检索中英文名称和关键词。
-   收藏和置顶正常工作。
-   最近使用最多保留 10 个工具。
-   首页首次访问不出现大面积空白。
-   相关工具关系正确。
-   页面刷新和直接访问路由正常。

## 23.2 隐私验收

使用 JWT、Cookie 和 Authorization Header 等敏感测试数据进行验证：

-   输入内容不进入 LocalStorage。
-   输入内容不进入 SessionStorage。
-   输入内容不进入 IndexedDB。
-   输入内容不进入 URL。
-   输入内容不进入浏览器历史。
-   输入内容不进入 Service Worker Cache。
-   输入内容不进入控制台和应用日志。
-   刷新后输入和结果不恢复。
-   离开页面后局部状态释放。
-   网络请求不包含用户输入和处理结果。
-   不存在非预期的第三方统计请求。

测试必须检查实际网络请求的 URL、查询参数、请求头和请求体。

不能仅通过代码中没有明显上传函数，就认定隐私验收通过。

## 23.3 PWA 验收

-   首次访问需要网络。
-   必要资源缓存完成后显示离线就绪。
-   首页离线可用。
-   工具目录离线可用。
-   20 个工具离线可用。
-   隐私页面离线可用。
-   首次缓存完成后，未曾访问过的工具也可离线打开。
-   所有工具核心功能不依赖外部 API/CDN。
-   用户输入和结果不被缓存。
-   新版本有明确更新提示。
-   用户可以暂缓更新。
-   用户确认更新后才刷新页面。
-   新版本必要资源先缓存再切换。

## 23.4 性能与内存验收

-   初始输入大小限制在执行前生效。
-   Base64 和哈希处理不会因不必要的数据复制造成明显额外内存压力。
-   接近输入上限的测试数据能够得到正确结果，或得到明确的资源限制提示。
-   不得静默截断输入或返回不完整结果。
-   大型任务不会永久阻塞主线程。
-   必要时能够取消任务或终止 Worker。
-   桌面和移动设备均完成代表性性能测试。
-   最终输入限制、测试数据和文档保持一致。

## 23.5 响应式验收

-   桌面端侧边栏正常。
-   平板端布局正常。
-   移动端导航正常。
-   工具页面布局合理。
-   Diff 页面适配移动端。
-   编辑器不超宽。
-   结果区域可滚动或折叠。
-   无明显横向溢出。

## 23.6 无障碍验收

-   核心功能可通过键盘完成。
-   焦点可见。
-   输入控件有标签。
-   图标按钮有可访问名称。
-   颜色对比符合目标。
-   错误提示可感知。
-   弹窗焦点管理正确。
-   Diff 不只通过颜色表达差异。
-   axe-core 自动检查通过。
-   人工键盘检查通过。

## 23.7 工程验收

-   TypeScript 类型检查通过。
-   ESLint 检查通过。
-   核心单元测试通过。
-   组件测试通过。
-   核心 E2E 测试通过。

# 24. Claude Code 实施约束

本 PRD 是项目实现的正式需求基线。

## 24.1 需求优先级

需求冲突时，优先级如下：

1.  本 PRD 明确写出的功能和约束。
2.  本 PRD 明确写出的安全、隐私和正确性要求。
3.  项目已有的技术约束和工程规范。
4.  常规工程最佳实践。

不得为了简化实现而擅自删除已确认功能。

## 24.2 禁止擅自扩展

不得擅自：

-   增加 MVP 工具。
-   增加账号系统。
-   增加后端。
-   增加数据库。
-   增加广告。
-   增加行为统计。
-   增加远程错误监控。
-   增加文件上传。
-   增加数据云同步。
-   改变工具 ID。
-   改变工具路由。
-   改变工具主分类。
-   改变已确认的隐私原则。
-   将工具输入和结果持久化。

如果确实发现需求存在矛盾或无法实现，先说明问题和影响，不得自行改变产品方向。

## 24.3 实施方式

采用小步迭代：

1.  先阅读 PRD。
2.  检查项目现状。
3.  制定当前阶段实施计划。
4.  明确本次修改范围。
5.  完成代码。
6.  执行相关测试。
7.  检查是否违反已有约束。
8.  总结完成内容和遗留问题。
9.  再进入下一阶段。

不允许一次性生成大量未经验证的代码后直接宣布完成。

## 24.4 工具开发约束

新增或实现工具时必须检查：

-   是否存在于冻结的 20 个工具清单。
-   ID 是否正确。
-   路由是否正确。
-   分类是否正确。
-   中英文文案是否完整。
-   注册元数据是否完整。
-   输入限制是否实现。
-   错误处理是否实现。
-   是否符合本地处理原则。
-   是否存在敏感数据持久化。
-   是否需要 Worker。
-   是否有单元测试。
-   是否有必要的组件和 E2E 测试。

## 24.5 安全与隐私约束

涉及 JWT、Cookie、Token、Authorization Header 等内容时，必须特别检查：

-   是否进入全局 Store。
-   是否写入 LocalStorage。
-   是否写入 SessionStorage。
-   是否写入 IndexedDB。
-   是否进入 URL。
-   是否进入日志。
-   是否进入缓存。
-   是否被发送到服务器。

发现任何违反要求的实现，必须先修正再继续。

## 24.6 代码质量

-   优先使用 TypeScript 严格类型。
-   避免不必要的 `any`。
-   避免重复实现公共功能。
-   核心处理逻辑与 UI 分离。
-   避免过度抽象。
-   避免不必要的依赖。
-   保持模块边界清晰。
-   重要逻辑编写测试。
-   不得通过删除测试或降低检查标准来规避失败。

## 24.7 文档同步

架构、工具注册、开发流程或部署方式发生变化时，必须同步更新相关文档。

不能让 README 和实际项目状态长期不一致。
