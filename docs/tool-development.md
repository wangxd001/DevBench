# 工具开发规范

## 新增/实现前核对
- 工具必须属于 PRD 冻结的 20 个工具之一。
- ID、路由、主分类必须与 PRD 一致。
- 中英文名称、描述、关键词、标签齐全。
- 注册元数据完整，相关工具关系合法。
- 核心逻辑与 UI 分离。
- 输入限制按 UTF-8 字节数计算并在执行前检查。
- 空输入、非法输入、边界和异常有明确处理。
- 输入和结果只在页面局部状态中。
- 不上传、不持久化、不进入 URL、日志、缓存或全局 Store。
- 按需评估 Worker；Regex 必须使用 Worker + 超时。
- 单元测试、必要组件测试和 E2E 已添加。

## 工具页面结构
至少包含工具名称、简短说明、输入区、必要参数、操作按钮、结果区、错误/状态提示、可折叠说明和相关工具入口。

输入和结果分离；结果不覆盖原始输入。简单转换可实时处理，复杂处理/生成按按钮触发，配置驱动型按需更新，不强制统一执行模式。

## 统一交互
按需提供清空、复制、下载、处理中、错误、空结果、超限提示和长结果滚动/折叠。不是每个工具都必须提供下载。

## 工具说明
至少包括用途、输入格式、示例、关键参数、常见错误和注意事项；不要求完整教程。

## 测试
覆盖正常、空、非法、边界、正确结果、复制、输入限制和异常处理，并按工具专项风险增加测试。

## 完成标准
工具功能、注册元数据、双语文案、输入限制、隐私检查、测试和相关文档均完成后，才能报告该工具完成。
