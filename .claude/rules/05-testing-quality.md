# 测试、验收与质量门禁规则

## 测试分层
- Vitest：核心处理逻辑单元测试。
- React Testing Library：组件与交互测试。
- Playwright：端到端流程。
- axe-core：自动无障碍扫描。
- 真实设备/浏览器：兼容性、PWA、离线和交互验证。

## 每个工具的最低测试覆盖
20 个工具均覆盖：正常输入、空输入、非法输入、边界输入、正确结果、复制行为、输入大小限制、异常处理。按工具特性补充专项测试。

## 必须关注的专项
- JSON：重复属性名、非法 JSON、深层嵌套、大输入。
- 日期：闰年、月末、夏令时、时区、无效日期、秒/毫秒单位。
- Cookie：Expires 逗号、重复 Set-Cookie、属性组合、非法输入。
- Worker：超时、取消、初始化失败、执行异常、意外终止、旧结果不得覆盖新结果。
- Base64/哈希：接近上限、UTF-8、多设备内存/耗时、主线程响应性、资源不足、不得截断/错摘要。
- PWA：首次缓存、离线首页/目录、从未访问工具离线打开、更新暂缓/确认、旧缓存清理。
- LocalStorage：损坏、版本不兼容、写入失败、存储不可用。
- 隐私：输入不进入 LocalStorage、SessionStorage、IndexedDB、URL、历史、Service Worker Cache、日志；无非预期网络请求。

## E2E
至少覆盖首页、目录、全局搜索、工具页、收藏、最近使用、隐私页、404；以及主题/语言切换、收藏/置顶、清空最近使用、刷新、直接访问工具路由、前进后退和离线访问。

## 质量门禁
按项目实际 package scripts 执行，至少覆盖：
- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run test:e2e`
- `npm run build`

若脚本名称不同，以 package.json 为准。关键检查失败不得报告通过；不得删除测试或降低标准绕过失败。生产构建应使用静态服务器预览验证。

## 验收证据
汇报测试命令、通过/失败数量、未执行项目及原因。区分自动化验证和真实设备人工验证。不得把未执行的测试描述为通过。
