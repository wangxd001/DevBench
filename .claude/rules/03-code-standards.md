# TypeScript 与代码质量规则

- 使用 TypeScript 严格类型；避免不必要的 `any`、类型断言和非空断言。
- 优先使用清晰、可读、可测试的实现；避免过度抽象和重复实现。
- 核心算法与 React 组件分离，尽量保持纯函数。
- 错误应通过明确的返回类型/异常边界处理，不得静默吞错。
- 空输入、非法输入、边界输入和资源不足均应有清晰行为。
- 输入限制按 UTF-8 字节数计算；在执行前检查。不得静默截断或返回不完整结果。
- 不把敏感输入写入错误消息、日志、控制台或遥测。
- 不得通过删除测试、降低 lint/typecheck 标准或屏蔽错误规避问题。
- 依赖应最小化；选库时检查维护状态、许可证、浏览器兼容、安全和包体积。
- 重要算法、边界规则和非显然的安全决策写必要注释；避免无意义注释。
- 用户可见文案放入国际化资源，不在业务组件散落语言三元表达式。
- 组件需具备正确语义、标签、键盘行为和可访问名称。
- 修改架构、配置、注册中心或工具开发方式时同步更新 docs。
