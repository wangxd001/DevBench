# Claude Code 开发工作流规则

## 每项任务开始前
1. 阅读 CLAUDE.md 和相关 Rules。
2. 读取 PRD 相关章节。
3. 检查 Git 状态、相关文件、package scripts 和现有测试。
4. 明确本次目标、修改范围、不做事项、验收标准和风险。
5. 如果 PRD 不明确或存在冲突，先报告并等待确认。

## 执行中
- 小步修改，保持每一步可验证。
- 不要一次生成大量代码后直接宣布完成。
- 不擅自改变工具 ID、路由、分类、产品范围或隐私原则。
- 不把临时 TODO 当作完成。
- 不使用模拟实现冒充真实功能。
- 依赖安装前说明用途；避免无关依赖。
- 不自动创建 GitHub Actions、Preview 环境或额外分支流程。
- Git 按 PRD：main 为唯一长期分支，直接在 main 开发提交。

## 每项任务结束
1. 执行与改动相关的测试。
2. 运行必要的 lint、typecheck、test、build。
3. 检查隐私、安全、响应式、国际化、无障碍和注册中心影响。
4. 更新相关文档。
5. 汇报修改文件、实现内容、测试结果、未解决问题和后续步骤。

## 变更管理
涉及产品方向、范围、安全/隐私承诺、数据持久化、网络访问、工具清单/ID/路由/分类、技术架构重大变化时，必须先说明影响并等待用户确认。不得自行把“建议”写入正式需求。

## 汇报格式
- 本次目标
- 实际完成
- 修改文件
- 测试命令与结果
- 尚未验证/失败项
- 风险或待用户决定事项
- 建议的下一步（仅一个最合适的下一步）
